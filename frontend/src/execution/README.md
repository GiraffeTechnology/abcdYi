# Read-only execution workspace

Revision 4 is an isolated host-integration candidate under the owner's later authorization. It does not replace the default App. `mountExecutionHost(container)` in `host.tsx` returns `update(context)`, `logout()` and `unmount()`. The existing embedding host passes its selected persisted `orderId`, nonempty `sessionKey`, optional selected `shipmentId`, and authenticated response-level `request(path, {method, signal})`. It retains ownership of login and credentials. Call `update` after identity, tenant, backend, transport or order changes; every update replaces the prior lifetime even if the session key is unchanged. Call `logout` synchronously when the host logs out. These functions are for host event handlers, not React render/effect callbacks. Do not copy the synthetic preview's session values into live usage.

`execution-host.html` is the separate integration entry. It starts signed out and performs no reads until the existing host supplies context via `window.executionHost.update`. It does not obtain login or selected orders from URL parameters, browser storage, or fabricated tokens. A real deployment must wire this API from its authenticated host; opening the HTML alone does not establish integration. `node tests/execution.host.build.mjs` builds it into `dist-execution-host` separately from the default bundle. `tests/execution.host.browser.mjs` verifies this boundary with explicitly synthetic intercepted HTTP responses and controlled session/transport replacement, logout, 401/403 and unmount. Provide `PLAYWRIGHT_MODULE` and `EXECUTION_PREVIEW_URL`; copy the prior synthetic fixture JSON into `../fixture-input.json` first. Those tests do not establish real API acceptance. A verified independent backend SHA, address, synthetic persisted order and existing session handoff remain required for that run.

Candidate baseline: `GiraffeTechnology/abcdYi` main `0c3b08b2e2e9163f18c0d7ae9281f3a380b6120f`.
This component is isolated from the default MyAivan entry. It is not mounted by `App.tsx` and does not authorize deployment.

The future host imports the named `ExecutionWorkspace` export and supplies `orderId`, `authenticated`, `sessionKey`, a stable authenticated `get` transport, and optionally a verified `shipmentId`. Change `sessionKey` whenever identity, tenant or backend context changes. Set `authenticated=false` synchronously on logout. Never place credentials or business payloads in URLs. The transport accepts `{method: 'GET', signal}` and must reject HTTP errors with a numeric `status` property; it owns authentication and must respect cancellation. Error response bodies are not displayed. Do not pass the legacy `apiFetch` error unchanged because its Error object does not expose numeric status.

The component requests the order first, then production, QC and execution events. It only requests shipments referenced by returned event payloads or explicitly selected by the host; a shipment response must match the selected order. It never writes business state, recalculates predictions, stores browser records, follows evidence URLs, or equates delivery with buyer sign-off. Only the order API's `buyer_signed_off_at` records sign-off. Missing values remain missing. Every returned QC failure remains visible. Unknown event types and correction payloads remain inspectable.

API paths: GET `/api/orders/{id}`, `/api/orders/{id}/production-monitoring`, `/api/orders/{id}/qc-records`, `/api/execution-graph/orders/{id}`, `/api/shipments/{id}`. Production expects `{milestones, monitoring_packet}`; QC and events expect arrays. 401/403 clear all component records; retryable errors are panel-specific. Requests time out after 15 seconds. Identity/order/session changes discard pending results.

QCRecordOut at this baseline does not return photo/report metadata, so only its actual summary fields are displayed. No order-scoped shipment-list endpoint is assumed. Main's production/QC query implementations do not consistently pass tenant context to their service query. Client-side shape checks do not repair server authorization; no tenant-isolation or real AC-3 acceptance is claimed here. Backend repair is outside this frontend task.

For a response-level authenticated host request, `createExecutionReadTransport` in `transport.ts` forwards the abort signal, forces GET, and preserves numeric HTTP error status without reading private error bodies. The component also validates the wire types it relies on, rejects wrong-order QC/events/shipments, and refuses malformed shipment references. These checks do not substitute for server authorization.
